Choose the smallest suitable runtime, then control access and capacity.

AWS
01 · DefineTerraform + VPC
02 · DeliverGitHub Actions + ECR
03 · RunECS or EKS
04 · ObserveCloudWatch + alerts

Security boundaries

Short-lived GitHub OIDC access, task-specific IAM roles, explicit ingress and egress, and secrets kept outside source control.

Cost decisions

Compare ECS and EKS against actual workload needs; right-size tasks or node pools, scale with demand, and budget for networking and logs.

Experience: Built an ECS delivery demonstration; reduced non-production EC2 spend by 26% through Karpenter and right-sized node pools.

Azure · Reference design

Deliver on AKS with identities and operating controls built in.

AZ
01 · DefineTerraform + network
02 · DeliverAzure Pipelines
03 · RunAKS + Helm
04 · ObserveAzure Monitor

Security boundaries

Entra ID and RBAC for people, managed identities for workloads, Key Vault for secrets, and network access scoped to the application.

Cost decisions

Size AKS node pools for real demand, autoscale suitable workloads, and review monitoring retention and network charges.

Experience: Delivered 10+ microservices to AKS through Azure Pipelines, integrated Key Vault and managed identities, and administered Entra ID RBAC.

GCP · Reference design

Give each GKE workload a clear identity, purpose, and capacity limit.

GCP
01 · DefineTerraform + VPC
02 · DeliverGit-based CI/CD
03 · RunGKE + Airflow
04 · ObserveCloud Monitoring

Security boundaries

Workload Identity Federation for GKE, scoped IAM permissions, controlled network routes, and separate access for each application.

Cost decisions

Right-size node pools and Airflow workers, scale workloads with demand, and track storage, data transfer, and log retention.

Experience: Operated workloads across GKE and Cloud Composer; later consolidated Airflow orchestration onto AWS and decommissioned the GCP cluster.
